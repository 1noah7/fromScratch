## Progress files and recovery

The compact **Progress files** menu beside the title offers **Export Progress** and **Import Progress**, also before starting a run. File selection uses RuneLite `Filepath.Chooser`; IO runs on the existing storage worker. Export first checkpoints the partial playtime minute without pausing gameplay. `.fsp` is a local ZIP with version-1 checksummed manifest, current schema number, character/run/revision metadata and exact checkpoint/journal/migration/playtime bytes. It contains no credentials or unrelated RuneLite settings. Keep exports private. The supported portable limits are 4 MB per entry/manifest, 256 MB total and 100,000 entries; unsupported or malformed archives fail safely.

The real chooser returns **null on Cancel** and a Filepath capability rooted at the selected file. Tests reproduce both contracts. Export builds/forces privately, then writes a new chosen file without accessing its forbidden parent or overwriting an older backup. Dated default filenames avoid collisions. Interrupted partial exports cannot validate on import; ordinary IO failures remove the new partial file. Duplicate entries are rejected case-insensitively for portability, and incomplete/corrupt relevant playtime is rejected before publication.

Import validates paths/duplicates/limits/checksums/schema/character, the full economic journal/archive chain and relevant playtime before presenting a dated run confirmation. Cancel deletes only its private staging tree. No divergent histories are merged. A changed local bank head invalidates the preview. After confirmation, playtime's FIFO drains and pauses; a portable pre-import backup is forced, the verified staging directory is moved into the character's own storage, and one checksummed local pointer is atomically replaced. Both economic and playtime repositories resolve that same pointer. Previous trees remain untouched. Damaged current bytes remain preserved, with an additional exact damaged-head copy when restoring over corruption. Pending bank/GE work is cleared only after acknowledgment; subsequent complete bank observations automatically compare against the restored anchor. Close other clients before importing.

Economic schema **9** and playtime schema **1** are unchanged. The local directory-selector envelope is version **1**, not a new accounting format. Invalid pointers or missing selected data block loading rather than creating a blank run. Atomic replacement is required; the previous bank-save fallback that copied over `current.json` on unsupported filesystems has been removed. A verified previous published head is forced into `previous.json` before current replacement. An orphan candidate is never automatically replayed.

After the first confirmed import, use an M9-or-newer build for this storage directory: older builds do not understand the restore selector. Originals and pre-import archives remain available, but downgrading is not an automatic merge/rollback mechanism.

When loading fails, the files menu additionally offers **Recover Previous Save**. It stages and verifies the prior published checkpoint and its chain, then uses the same explicit replacement confirmation/import mechanism. A valid current head is never replaced by this recovery shortcut. Newer progress can be absent from a previous checkpoint; the confirmation warns about this and retains original evidence. If no verifiable prior checkpoint exists, a compatible exported backup or manual recovery is required. There is no automatic reset or guessed latest-orphan recovery.
