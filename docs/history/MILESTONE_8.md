## API investigation and feasibility

Resolved RuneLite **1.13.3**, Java 11 target, unchanged Gradle Wrapper. Inspected installed client/API source jars, including ExaminePlugin, ChatMessageManager, BankTag, TagManager, BankTagsService, BankTagsPlugin, TabInterface, BankSearch and playtime-related Client/VarPlayerID/VarbitID definitions.

- Native Examine: the core uses EXAMINE_ITEM_GROUND and widget CC_OP_LOW_PRIORITY, followed by ITEM_EXAMINE responses. Known WORNITEMS/SMITHING child positions and normal widget children follow that implementation. We never consume or change the event or add a menu. An expiring FIFO guards rapid requests; unknown item contexts consume a sentinel without output. Core's optional "Price of" ITEM_EXAMINE lines do not consume requests. The supplement uses queued GAMEMESSAGE, preventing recursion. The initial priority 1 queued our line too early; the correction uses **priority -1**, after core Examine's priority 0. Queue order is native description → optional core price line → From Scratch. Messages drain in RuneLite's normal chat processing cycle; rapid native responses retain FIFO item correlation. Unknown/missing definitions, expired requests and changed characters/runs are skipped.
- Bank Tags: the actual filter callback calls BankTag.contains(itemId). registerTag/unregisterTag, openBankTag(String,int), closeBankTag and BankSearch.layoutBank are public and sufficient. The internal proof uses the real BankTag interface, native-service adapter seam and controller→forced repository→overlay/filter sequence. No fake slots or gameplay actions are needed. **Normal live withdrawals/deposits still require user verification**; API/source and mock proof are not live acceptance.
- No suitable continuously available account-wide playtime counter was confirmed. ACCOUNT_SUMMARY_DISPLAY_PLAYTIME is a display preference; TRACKING_PLAYTIME_LEAGUES is league-specific. Use logged-in host GameTicks instead. Mobile and other clients' playtime is not reconstructed.

Reference implementations: [ExaminePlugin](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/plugins/examine/ExaminePlugin.java), [BankTagsService](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/plugins/banktags/BankTagsService.java). ## Behavior and limits

`ExamineFormatter` reports the saved effective **virtual bank quantity**, item name, GE/HA totals and positive unit quotes in the standard item-price style. For example: `From Scratch: 199 x Law rune: GE 23,283 (117ea); HA 28,656 (144ea)`. Zero says **Locked** and a negative says **Outstanding**, describing the bank display rather than physical outside-bank ownership. Totals use checked signed multiplication; missing GE quotes are explicitly unavailable (or omitted beside a buyback), nonpositive/missing HA is omitted, stale GE quotes are marked. Zero-quantity buybacks omit unhelpful zero price totals. No buyback price is used as market value.

Only **From Scratch:** and numerical segments use the live existing **Virtual quantity color** setting. Balanced color tags close each highlight; item names and all ordinary words/units use native normal chat text, including RuneLite's configured server-message normal color. Redundant/unresolved ChatColorType.NORMAL tokens are no longer emitted. String appends escape Jagex markup and names cannot inject the native pipe delimiter. Notes/placeholders resolve to real IDs where supported; genuine equipment variants remain distinct. No physical inventory/equipment quantity is treated as virtual ownership. No price requests, save writes or game actions occur in this path. Core Examine retains its output. Third-party plugins spoofing ITEM_EXAMINE outside the inspected core pattern cannot be identified reliably by the API.

### Missing-prefix regression

The missing beginning was caused by a **literal pipe (`|`)**, not message length. In the installed native chat scripts, BUILD_CHATBOX (216) reaches script 84; instructions 1639–1654 detect the first pipe and call script 632. That script splits `name|body`, and the caller uses the suffix as the message body. This exactly reproduces all five reported outputs: Coins had no pipe; Law/Pouch kept only HA; Cosmic kept GE/HA; Fire Cape kept Buyback/HA. A non-suspending logpoint in an existing JUnit fixture captured the complete old colored formatter payload before submission, including its intact prefix and first pipe. Installed RuneLite 1.13.3 chat queue/client insertion code did not truncate that payload. The native scripts were inspected read-only; no game input or live gameplay testing was performed.

Use semicolons instead of the reserved delimiter, short **GE/HA** labels and balanced color tags. Optional pricing has a **160 visible-character readability budget**, not an asserted native transport limit: whole price fields are omitted when they would exceed it, GE before HA. Mandatory prefix, signed quantity, complete escaped name, status and buyback payment are never sliced. Tests apply the native first-pipe split to the final colored payload, include the old failure as a negative control, and check both sides of the optional-field boundary. Actual chat canvas wrapping and visual placement remain user-only acceptance.

Buyback information uses the existing catalog, entitlement levels and recorded payments, with no second price table. Locked entries show the current challenge unlock/set/upgrade cost. Paid entries say **Buyback: Unlocked (1000K GP paid)** (or **set paid**), even when the effective bank quantity is zero. Rune Pouch/Divine/Trouver forms share the same one-time receipt. Void base+upgrade receipts accumulate for Elite, without quoting a duplicate purchase. Pouch contents/offsets and financial history are untouched.

The earlier source did implement and wire a primary-panel Virtual Bank button; it was not deliberately deferred. Source alone does not establish why that button was absent in the live client's display. The final check confirms that RuneLite 1.13.3's public dynamic BankTag filter invokes membership by item ID and uses the existing native bank build, with ordinary game interactions left intact. No unsupported widget manipulation is needed.

The correction replaces that button with **Enable Virtual Bank View**, a RuneLite configuration option that is **disabled by default**. Enable core **Bank Tags** and this option, then open the bank: only positive committed effective balances match, including paid-copy buybacks. An active user Bank Tag takes precedence; selecting normal bank viewing allows this filter to activate. Missing Bank Tags leaves ordinary banking intact; the option's description explains the dependency. Disable the option for normal viewing. The temporary unique tag has no saved layout or modification controls; close/disable unregisters only our tag, preserving user-created tags/layouts. Membership refreshes only after acknowledged positivity changes; unchanged revisions do no map scan, and dependency discovery is bounded per bank-open/availability change. Native search, tabs, scroll, drag and quantity controls remain owned by RuneLite/OSRS. Live interaction/Plugin Hub approval remains unclaimed.

**Mixed stacks:** a native stack can contain 110 physical sharks while the From Scratch counter is 10. Filtering admits the item type, not ten separate units. Normal Withdraw-All remains capable of withdrawing legacy copies. No menu/action restrictions are implemented.

Item History: in either Bank History view select a row and click **Item History**, or type a known item name in the search field and use the same button without a selection. The read-only view pages deposits, withdrawals, corrections, automatic adjustments, pouch offsets, family/set buybacks and observed GE executions. Physical and virtual changes are distinguished. Existing GE matches are possible attribution, so the view does not claim verified collection origin/profit. Search suggestions use known legacy/current/progression item types; GE-only types not seen in those sets remain in their separate GE history. Offline transactions absent from the ledger cannot be invented.

Time Played shows truncated whole minutes below 60 minutes, hours below 24 hours and days thereafter, with correct plurals. Old run timestamps remain untouched. First M8 observation establishes zero measured ticks; no old run age is converted. Host-only scope is in the tooltip. Active, verified, logged-in ticks count; login screen, disconnects, closed/disabled client and mobile do not. Repeated tick callbacks are deduplicated; loading/hop intervals add no elapsed duration.

## Persistence and performance

Economic format **9 is unchanged**. Initial legacy snapshot, signed P/B, buybacks, pouch adjustments, financial/GE history and run identity/start remain intact. The lightweight checksum-protected playtime format-1 checkpoint lives in the existing character directory's `playtime` subdirectory, keyed by run UUID. Previous exact bytes remain as a backup. Candidate/backup are forced before atomic current replacement. Corrupt/missing-with-recovery/incompatible counters are preserved and shown as unavailable rather than zero. Restoring a damaged playtime checkpoint is an explicit recovery action, not an automatic bank reset. Old-run counters survive reset but cannot attach to a different run.

Only the dedicated FIFO worker writes playtime, normally once per 100 ticks (~60 seconds); partial batches flush on interruption/context change/disable. An unexpected process crash can lose up to the uncheckpointed minute. A loaded revision CAS rejects overlapping concurrent-client intervals instead of adding twice; contention can conservatively undercount, never invent overlap. Atomic-move-unsupported filesystems leave recovery evidence and an unavailable counter, with bank accounting unaffected. No per-tick journal, financial migration, network request or filesystem IO on client/EDT. Time tile updates every ten ticks without rebuilding the sidebar. Native input lag and interaction correctness remain unmeasured until the user's live comparison.

## Manual acceptance (user only)

Launch with `.\gradlew.bat run`; use RuneLite's [Using Jagex Accounts](https://github.com/runelite/runelite/wiki/Using-Jagex-Accounts) instructions. No account input is automated.

1. Load the existing run. Confirm saved bank GP, worth, buybacks, pouch deficits and GE history. No new baseline/attestation should be requested.
2. Examine Coins, positive Law rune, negative Cosmic rune, purchased Rune Pouch/Divine and locked Fire Cape. Every supplemental line must retain **From Scratch: [signed quantity] x [name]**. Verify native description → enabled core price information → exactly one From Scratch item-price line, including narrow/expanded chat. Check **Locked**/**Outstanding**, signed totals/positive unit quotes, paid shared pouch status with one cost and no HA-zero clutter for locked Fire Cape. Also check unpriced, noted and native-placeholder items. Change Virtual quantity color: only the next line's prefix/numbers change; item names/ordinary words stay normal. Rapid different examines must not swap IDs or recurse. NPC/scenery Examine adds nothing. Logout/character changes discard old requests.
3. Confirm **Enable Virtual Bank View** is off by default and ordinary bank viewing is intact. Enable core Bank Tags and the From Scratch setting; open bank and confirm only positive types, ordinary native withdraw/deposit/drag and unchanged OSRS labels/counters/tint. Deposit a new type: it appears after commit. Withdraw its last positive unit: it leaves the filter. Check buybacks, mixed stacks, placeholders, native search/tabs/scroll, partial rows, resize and custom colors. Select a user Bank Tag: From Scratch must not take it over. Disable/re-enable the setting and both plugins, close/reopen bank and verify user tags/layouts survive. Disable the option for ordinary viewing; with Bank Tags disabled, banking remains normal.
4. In Automatic/Manual Bank History, select an item then Item History; also search a name with no current-page match. Verify full-item pages, deposit/withdrawal signs, corrections, pouch offsets, buyback price, separate observed GE evidence, Close and pagination. No changes to balances/history from viewing.
5. Time Played begins at **0 minutes** for this new measurement baseline. Stay logged in >1 minute; confirm **1 minute**. Logout/disable for >1 minute: that time must not accrue. Hop/reconnect without duplicate time. Restart normally: measured minutes persist, run start/identity remain unchanged. Hour/day boundaries are covered by fixtures; no need to wait days. Mobile time is excluded.
6. Compare ordinary banking speed with From Scratch enabled/disabled and Virtual Bank on/off. Confirm no new delay. No live performance or Plugin Hub approval is claimed.
