## Acquisition pipeline correction

The collector retains aggregate increases reliably observed outside banking against the exact last acknowledged Holdings. It preserves this receipt until that immutable observation is committed/acknowledged, even if the bank opens and the item moves before the next quiet tick. Only personal item IDs are checked for this hint; the cached bank is not copied again. A supported ground Take menu action supplies a short-lived corroborating hint, requiring an actual matching physical change. No menu event is consumed or altered.

The reducer still matches source/destination legs first and excludes known dropped returns. Ordinary observed acquisitions and subsequent inventory/bank/equipment transfers can commit automatically. Unmatched bank increases without receipt evidence, unsupported sources, transformations and unexplained decreases remain explicitly reviewed. Source uncertainty never becomes an automatic gift/acquisition.

Normal session startup collects a safe full observation automatically. Unchanged or fully matched transfer-only changes reopen tracking without a manual Update Progress action or speculative acquisition. Missing data is unknown, with a secondary observation instruction. Meaningful unresolved discrepancies require player review. Stale tokens, changed holdings, bank closure and newer on-disk revisions reject application rather than overwriting progress.

## Exact legacy-deficit design

Earned ownership and location allocations remain nonnegative longs. `LegacyBankDeficits` separately stores nonnegative outstanding bank withdrawals D by item identity. The display is:

`signed bank balance = earned copies available in bank - D`

For a physical transfer q, retain virtual-first allocation `v = min(q, earned source quantity)`. A bank withdrawal adds `q - v` to D; a legacy deposit repays `min(D, q - v)`. Earned transfers never create or repay a legacy deficit. Pure inventory/equipment movement does not change D. Explicit note links share the supported base identity; arbitrary variants are not merged.

100 legacy shields: 0 -> withdraw one -1 -> withdraw another -2 -> return both 0. Earn/deposit three -> 3. With three earned bank copies and two outstanding legacy withdrawals, display 1; earned total remains three. Withdraw four from three earned plus legacy -> three earned move out and D increases by one. Returning the four restores earned bank copies and repays only the legacy part. Lifetime acquisitions do not change when D is repaid.

Zero/negative display retains accepted dimming; positive display renders normally. Signed formatting adds a minus without permitting negative earned ownership. Tint color/opacity, bounds, quantity positions, clipping, tabs/search/drag handling and inputs stay as accepted in M3. No game quantity, ID, sprite, asset, widget, menu or click zone is modified. Missing bank slots are not created: retained deficits, with names and “not currently in bank”, appear in Account Tools.

Use Update Progress -> Show unchanged items -> Resolve legacy withdrawal for a confirmed outstanding counter, or Advanced quantities to declare/correct an amount. This appends an explicit deficit delta in the same commit as ownership decisions. Older M4 saves did not record deficits, so counters begin at zero on migration; do not invent historical deficits from incomplete/variant transfers. Earlier outstanding amounts can be declared manually without changing acquisitions.

## New player workflow

Initial-run setup retains Prepare Your Account and its confirmation safeguards. Active dashboard: Total Value Gained, Current Net Worth, Spendable GP, Active Run Duration, Items Unlocked, Recent Acquisitions. Financial values remain placeholders. The old Lost / Spent placeholder is removed from the primary dashboard.

Account Tools below the dashboard contains **Update Progress** and the description: “Played on mobile or another computer? Update your From Scratch progress when you return to this PC.” It also holds outstanding deficits, protected Reset and collapsed Transaction History at the bottom. Only meaningful pending changes expand the observation/review workflow; unchanged sessions require no approval.

The editor defaults to changed items only, including vanished legacy-only types. 1,000 unchanged holdings plus three differences show three rows. It offers item-name search, numeric sorting, All Changes/Gains/Losses/Needs Review filters, optional unchanged items and selected-row bulk actions. Applicable decisions include Newly Earned, Existing Legacy, Returned Item, Lost / Consumed, Resolve legacy withdrawal and Custom quantities. Bulk selection is converted from sorted view indices to exact model IDs and validated before any row changes.

Newly Earned uses net gained copies, or one copy for an explicitly revealed unchanged item; Advanced quantities supports another amount. Existing Legacy preserves known earned copies while rejecting new ownership. Returned Item avoids another lifetime acquisition; Lost / Consumed prevents reserving the newly removed copies for a future return. Elsewhere allocations remain bounded and are preserved by classification actions. Each decision is auditable, with an optional additional explanation.

Review and apply presents a summary of changed types, selected decisions, net earned copies, names and before/after earned/deficit quantities. Cancel never saves. The controller revalidates identity/session/complete current holdings/open bank/token before storage; compare-and-swap prevents overwriting newer progress. If unchanged, the editor says “No item changes detected.” Completely away-and-consumed activity cannot be reconstructed from final holdings.
