## Milestone 3 update

Gradle dependencyInsight confirms client/API 1.13.3, Java 11, with the unchanged Wrapper/dependency layout. From Scratch explicitly hooks only gameval InterfaceID.Bankmain.ITEMS. The final correction uses a manual/dynamic Overlay rather than inheriting WidgetItemOverlay's callback-list enumeration.

Read-only javap inspection of the installed official injected-client 1.13.3 artifact established the top-row omission: the renderer updates item widget canvas coordinates, then adds a WidgetItem to the callback list only if its origin x/y lies within the current clip. It does not test the full rectangle for intersection. A top-clipped item is therefore still partly drawn but absent from that list, while a bottom-clipped item with its origin inside can appear in it. Client source OverlayRenderer.renderAfterLayer exposes that list through OverlayManager.getWidgetItems; WidgetItemOverlay merely iterates it. [Official OverlayRenderer source](https://github.com/runelite/runelite/blob/master/runelite-client/src/main/java/net/runelite/client/ui/overlay/OverlayRenderer.java), [WidgetItemOverlay source](https://github.com/runelite/runelite/blob/master/runelite-client/src/main/java/net/runelite/client/ui/overlay/WidgetItemOverlay.java).

Production uses only public APIs: enumerate actual graphic item children of Bankmain.ITEMS, require matching component/direct parent/visibility, and include bounds intersecting the item viewport. The viewport is the ITEMS bounds intersected with ITEMS_CONTAINER bounds, further clipped to the incoming graphics clip. It excludes tabs/search controls and treats both scroll edges identically. Full item bounds determine text positions. BLANKOBJECT and fillers are skipped. The callback list remains useful for a provided drag rectangle; if an active clipped-origin drag lacks one, its floating effect is omitted temporarily rather than guessed. No private/obfuscated members, reflection or bytecode access is present in plugin code. The inspection was offline, not a live-client test.

RuneLite's built-in QuantityFormatter only has K/M/B suffixes; From Scratch's integer formatter also covers T/Q/E to retain correct long-range magnitude without overflow. Labels are computed on immutable projection updates, not per frame. No price/network/persistence calls occur in painting. The only item-definition lookup is cached placeholder classification; actual frame time remains unprofiled in-game.
