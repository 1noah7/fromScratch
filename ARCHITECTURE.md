# Architecture

M1–M8 are user accepted. **M9 awaits manual acceptance.** Personal-container ownership and cloud remain outside scope. The previous multi-container design is preserved only in [historical documentation](docs/history/ARCHITECTURE_MULTI_CONTAINER.md) and test fixtures, not live plugin wiring.

## M9 hardening

Interactive native Bank Tags filtering is restored, default on without overriding explicit saved off preferences. A cached immutable membership set makes contains() a pure lookup. Coalesced client-thread tasks guard lifecycle re-entry and clear ownership before synchronous core operations. Relayout occurs only on changed positive membership. Full physical-container observations remain independent; initialization never filters. See the latest M9 restoration notes and live-acceptance limitations.

`persistence/ProgressBackup` writes bounded version-1 `.fsp` ZIPs with exact-byte hashes and economic schema 9 metadata. Import validates in an unselected staging tree, checks current-head fingerprint, archives prior files and atomically publishes one character-local directory selector. Both repositories resolve that checksummed selector, so bank and playtime switch together; old trees survive. Playtime drains/pauses only for confirmed restore. IO and history validation remain on the storage worker; context guards reject stale callbacks. Economic/playtime schemas and reducers do not change. Before current replacement, a forced previous published head is kept; unsupported atomic moves fail without overwriting current. Explicit previous-save recovery uses the same verified import path, never guessed orphan replay. See [M9 evidence, limits and CI blocker](docs/MILESTONE_9.md).

## M8 informational components

`examine/NativeExamine` uses the core 1.13.3 Examine action/widget pattern, a bounded expiring FIFO of item requests and ITEM_EXAMINE responses. Its priority -1 subscriber queues one GAMEMESSAGE after core Examine (priority 0) queues its optional GE/HA line. Core "Price of" supplements are ignored for correlation; unknown widget requests consume a sentinel response. Lifecycle and verified run/character changes reject stale requests. `ExamineFormatter` centralizes escaped item names, signed virtual bank counts, checked GE/HA totals and catalog/receipt-backed locked or purchased buyback information. Prefix/numbers alone use the live existing virtualQuantityColor setting; balanced closing tags restore native/RuneLite normal chat text. Native chat interprets the first literal pipe as a name/body separator, so output uses semicolons and sanitizes pipes in names. Whole optional price fields have a 160-visible-character readability budget; required opening/status/payment are never sliced. See [native-script regression evidence](docs/MILESTONE_8.md#missing-prefix-regression). No HTTP, disk IO or accounting changes run here.

`bank/VirtualBankMode` registers the supported core dynamic tag only for an active anchored run, respects native/user-tag selections, restores the friendly/native title, and cleans up its own tag. Failure latches avoid retry loops. No fake bank, layout deletion or native action interception.

`ItemHistory` projects existing immutable audit evidence; `BankRepository.itemHistory` filters before bounded 25-row/64-segment pages. It runs on the existing guarded background history path. Search uses known bank/legacy/high-water item names and does not scan the full ledger on each keystroke. Observed GE executions are included as independent evidence; current possible matches never become a claim of verified bank origin.

`playtime/PlaytimeTracker` counts deduplicated logged-in GameTick callbacks only for a verified loaded active run, using 600ms per tick. Its dedicated FIFO worker checkpoints every 100 ticks (about one minute), and flushes partial batches on interruption/context change/disable. Shutdown queues final work then terminates at the FIFO tail without blocking. `PlaytimeRepository` uses a separate character/playtime directory, run UUID, checksum envelope, forced candidate, exact prior backup and atomic replacement. Its CAS discards overlapping stale-client intervals rather than counting them twice. Error/unknown files never become a blank zero; recovery evidence is retained. No bank schema bump or economic journal entries. The EDT updates only the Time Played tile, with no wall-clock timer or panel reconstruction. See [validation/limitations](docs/MILESTONE_8.md).

## Observation lifecycle

BankPlugin in the actual resolved RuneLite **1.13.3** uses `InterfaceID.BANKMAIN`, `InventoryID.BANK`, WidgetLoaded/WidgetClosed and ItemContainerChanged. The implementation follows those public constants and `Client.getItemContainer(InventoryID.BANK)`. WidgetLoaded alone does not guarantee item availability, and ItemContainerChanged need not fire on every reopening.

GameTick retries a mounted, visible normal bank excluding PIN interfaces. Interface/BANK events invalidate the cache. The next GameTick (API 1.13.3: after packet processing) captures it once. There is no first-scan restart or two-more-tick debounce. Unchanged ticks reuse the immutable snapshot. Already-open banks work through mounted interface checks. Zero-length complete arrays are valid; null arrays/containers, null slots and negative quantities never become zero observations. A stable API bank has no additional server completeness flag; the public observation boundary cannot prove hidden future packets will not arrive. Later events invalidate/retry it.

Exact API IDs and aggregate quantities are authoritative. Widget item layout/search/tab filters never enter accounting. Rearrangement with equal aggregates writes nothing. Personal and game menu events are not subscribed. Closing before a stable observation defers the net comparison until next opening. Outside-bank events never change P/B; M6 GE audit/attribution uses the separate path below. Ordinary world loading/hopping does not introduce an approval gate; identity/logout/plugin boundaries reset session observation safely.

## Commit path

1. Client thread captures a complete bank at a game-tick boundary and queues the immutable observation.
2. The single storage worker runs BankEngine and prepares the next audit against the last acknowledged run. Existing state remains authoritative.
3. One bounded background worker obtains Filepath/character lock, validates expected current revision and candidate deltas, writes/forces/verifies a new immutable journal and checkpoint, then publishes current via atomic move or recoverable forced-copy fallback.
4. After successful durable acknowledgment, a client-thread callback rechecks lifecycle/context/character and publishes the new run to overlay/Swing.
5. Failure retains the old in-memory and persisted cursor. Error/reload blocks inconsistent speculative state; orphan files are retained but never replayed. If publication completed before acknowledgment was lost, reload adopts the durable checkpoint without replaying its bank delta.

No IO runs on the client/EDT or renderer. Shutdown cancels queued work without blocking. Per-frame rendering only reads immutable cached balances/labels/settings and item geometry. Full journal/archive verification occurs on load; normal commits verify current/head rather than rescanning the entire history.

## Format 5 and migration

The new envelope stores character/run/start/previous-run identity, revision/sequence, immutable initial bank, physical bank anchor, sparse signed balances, anchor readiness, recent bank audit and persisted first-comparison host summary. A migration additionally retains the exact original envelope text plus a safe local archive reference. Legacy header schema 1 is preserved inside that original document; it is not reinterpreted as an active multi-container header.

Each `bank-ledger-<revision>.json` segment has a checksummed audit, character/run, sequence, previous revision and result-checkpoint digest. Checkpoints and pending files are immutable/recoverable; current is the only published authority. Recent UI history is bounded to 30 batches, but complete journal files remain. There is no replay of unreferenced orphan batches.

Verified formats 1–4 migrate through the historical codec and original-format journal digest verification. Before changing current, copy all original JSON save/ledger files into a unique migration directory, force each copy, compare exact-byte SHA-256, then force a manifest and verify it. Originals remain as well. Preserve run/start/baseline and old signed bank display. Legacy personal/Elsewhere/acquisition history is archived, never fabricated as bank earnings. One confirmed complete bank anchors an imported active run without replaying earlier changes. Excess positive balances require explicit listed reductions or physically banking those copies first. Reset has the same archive-before-acknowledgment discipline. No actual private save was inspected/migrated by development tests.

## M5 financial extension

The earlier format-5/polish sections describe the accepted M4 foundation. Current format **6** retains its quantity model and linked bank journal while extending BankRun with FinancialState and BankAudit with ValuationEvent evidence.

- PriceService owns a separate cancellable daemon scheduler. It calls injected public RuneLite ItemClient.getPrices only there, indexes the bulk GE-guide records and atomically replaces an immutable market snapshot. A failed refresh retains the prior data/time with stale status. No character IDs or holdings are sent. The cache refresh interval is 30 minutes with one-minute retries. Market receipt time is explicitly not the feed's market-update timestamp.
- RuneLiteBankSource resolves note→linked unnoted price identities on the client thread, once per encountered exact item ID. Other variants stay distinct. Cache registration/lookup performs no HTTP. Game data access is never moved to a storage/HTTP worker.
- FinancialEngine calculates high-water deltas on the existing serial storage worker using cached immutable quotes. No price availability gate delays a bank commit. Gain UUIDs are derived from the bank-audit UUID/kind/item. Unknown/stale historical quotes are persisted as unpriced evidence, never retroactively repriced. Manual count correction/anchor can only raise a comparison ceiling without gain.
- BankRepository validates quantity and financial transitions, then publishes journal/checkpoint/current with the existing force/CAS/recovery guarantees. A failed write cannot publish either new bank or historical financial state. New events remain linked to original bank audit/time/session/run/character context. Full evidence stays in journal segments; checkpoint totals/high-water maps avoid full-ledger scans during ordinary banking.
- Rolling checkpoints retain the new head's full gain evidence and compact older gain/host-comparison summaries. Complete quotes stay in the original immutable journal/checkpoint, never deleted or repriced. This avoids copying a large gain-price batch into 30 later snapshots; explicit recent expense records remain readable. A regression verifies old journal bytes and gain quotes remain unchanged.
- BankValuation runs on the worker as a derived calculation after committed state or market-version changes. Arbitrary-precision intermediate sums avoid order-dependent overflow; out-of-long-range totals are unavailable. Revision/lifecycle/character checks reject stale callbacks. Price-only refresh publishes a BankView without disk writes, new sequence or overlay-label reconstruction.
- Bank GP is the persisted signed balance for ItemID.COINS, never a second wallet. Explicit expense records are separate statistical events and do not alter P/B or coin balances. BankExpenseDialog requires positive GP, a reason and confirmation; the loss tile supports mouse and keyboard entry and displays recent explicit records. Normal withdrawals never become spending.
- BankPanel still constructs its two-column tree once, updates labels/tooltips only and retains M4 reset/attestation safeguards. Missing current prices show a Priced subtotal label. BankTooltips formats escaped, width-limited Swing HTML with exact GP and plain-language unknown/older-price counts; persistent timestamps and migration details stay outside ordinary tooltips. Item stack and compact GP labels share one integer formatter: exact below 10,000, uppercase K below ten million, uppercase M thereafter. Money appends GP while detailed tooltips retain grouped exact amounts. Both manual tiles use the cached Purple partyhat; correction purpose text distinguishes mistakes from ordinary mobile return.

Before a format-5 migration, verify the old full chain, archive all original JSON byte-for-byte with forced manifest/hash verification, then append a FINANCIAL_BASELINE event linked to the old head. Preserve original P/B/identity/start/snapshot/history. H=max(0,B), zero prior financial totals and an explicit imported measurement timestamp avoid invented history. The financial archive reference remains verified on load. Formats 1–4 retain existing historical decoding/archives and one-time bank anchor. No private save was used by development tests.

## M6 passive exchange extension

`ge/RuneLiteGeSource` copies the public offer fields on the client thread, ignores unverified initial EMPTY and nonlive environments, seeds nonempty current offers once after login, and resets its connection context on login/hop/loss. Offer events enqueue immediately; GameTick also seeds/drains any available snapshots before bank observation. No personal containers, GE widgets, menus or native actions are inspected/changed. Missing GE information never becomes a bank prerequisite.

`GeObservation` carries immutable input, event/session identity and explicit pre-start lifecycle evidence. The latter avoids inferring known legacy provenance from equal/coarse/adjusted timestamps. `GeEngine` derives local generations from run/slot/input identity, checks offer fingerprint and monotonic cumulative quantities/GP, records only increments and preserves initial-snapshot/offline/reuse uncertainty. Unchanged resumes update connection metadata without fills, allowing later legitimate clears/reuse. EMPTY records a cleared slot with unknown destination, not a cancellation. Terminal-state regression cannot recreate refunds. `GeTrade` keeps reported totals/derived-average evidence, original item/name, observation time, origin and fee method; profit remains unknown.

BankController serializes GE and complete bank observations in one FIFO with existing durable acknowledgment guards. Under an extreme burst it retains the latest cumulative snapshot per slot with uncertainty, leaving queue capacity for bank snapshots. Metadata-only GE commits reuse immutable preformatted overlay labels. GeEngine's bounded matching state has at most eight offers, 256 credits, 128 unmatched withdrawals and 30 recent trade rows; full history remains in immutable journals. Possible matching consumes units/GP once, including coins/platinum equivalents, and cannot independently change P/B.

An automatic bank operation derives its matching evidence before FinancialEngine recognizes new high-water gain. Possible conversion amounts are excluded from that operation's gain estimate; the high-water ceiling still rises. Persistence independently recomputes both reducers to validate the same exclusions, GE state and financial totals atomically. Estimated seller fee totals live in GE state and are combined with explicit expense totals only in the dashboard read model, with an estimated marker. Neither changes Bank GP. Old M5 estimates/quotes remain unchanged, even when trade evidence arrives too late to classify an earlier operation.

Format 7 adds required GE state and optional per-audit GE evidence. Format-6 load verifies the old full chain, forces/verifies an exact-byte archive, then appends EXCHANGE_BASELINE to the linked journal without modifying identity/start/initial bank/P/B/financial history. Older financial/legacy migrations retain their original guarantees. Current/journal/checkpoint hashes and archive manifests remain checked; missing/newer/corrupt/interrupted state cannot become default empty progress. There is no separate external database/backend.

BankRepository pages at most 25 GE rows / 64 segments per request off the client/EDT, with run/character/context validation. GeHistoryView provides page-local name search, numeric sorting and activity/uncertainty filters, cached RuneLite sprites and readable exact details. It disables HTML parsing in item labels. ## M7 curated buybacks

`buyback/BuybackCatalog` defines fixed prices and exact gameval variants under stable catalog/equipment-role identities. `BuybackEntry`, `BuybackPurchase` and `BuybackState` are immutable; the bounded purchase list validates its own prices, tier transitions, unique IDs and cumulative committed GP. Serialized roles explicitly carry quantity one. `BuybackEngine` owns eligibility, available GP and deterministic physically bounded bank projections, independently of Swing/rendering.

BankController accepts a revision-bound catalog/purchase ID only with a fresh complete bank equal to committed P. RuneLiteBankSource checks the actual ItemComposition untradeable/note/placeholder predicates on the client thread. BankEngine produces one BUYBACK audit containing payment evidence. The existing worker/Filepath CAS save independently recomputes eligibility/payment/entitlement state; failed persistence never publishes a purchase. Other bank and GE commits preserve buyback state. Reset still archives before clearing the active run.

Raw B and immutable L never change on purchase. Each paid role stores a nonpositive bank floor, initialized at its current aggregate raw progress and raised toward zero on later returns. This permits buying one still-banked copy despite prior legacy withdrawals, without multiplying the grant when those withdrawals return. Floors advance atomically and are independently recomputed by persistence; upgrades preserve them. Effective item projection permits at most one paid unit, physical capacity and Void tier, with virtual-first reductions. Effective coins are raw B(COINS) minus committed payments. Both overlay and BankValuation use that projection; bank arithmetic/high-water/GE engines continue to use raw B. Net worth includes the coin adjustment once; historical gains remain fixed. Displayed confirmed spending adds the separate committed total once. Price refresh is still derived/no-save work.

BuybackView/BuybackDialog reuse BankIcons and BankDialogs for the categorized/searchable shop, concise confirmation and separate bounded history. Async sprite completion repaints retained table labels. BankPanel adds two matching tiles after GE, without reconstructing existing dashboard components on bank events. Catalog history is limited by its 26 entries; no normal event scans a full bank/GE journal. Shop closes after confirmation; reopening reads current committed state. Stale confirmations are rejected.

BankRunCodec/BuybackCodec format 8 require explicit buyback state. Verified format-7 load archives every original checkpoint/ledger byte with forced/verified manifest, appends BUYBACK_BASELINE and preserves run/start/initial/P/B/financial/GE data. Earlier codecs/migrations remain supported; all archive references are checked on load. Quantity/accounting, persistence, UI and renderer remain separate.
